# التقرير الختامي والتوثيق التقني الشامل: نظام تغطية مزودي الخدمة (Agency Coverage API)

**رمز التذكرة:** `[P3-T3]`
**الميزة (Feature):** CRUD Operations & Spatial Validation for Agency Coverage Polygons.
**الإصدار:** 1.0 (تم الإطلاق والدمج بعد اجتياز المراجعة الصارمة).

---

## 1. ملخص تنفيذي (Executive Summary)

تم بنجاح إتمام وتأمين واجهات برمجة التطبيقات (API) المسؤولة عن إدارة وتحديث مناطق التغطية الجغرافية لشركات تقديم الرعاية الصحية (Agencies) على منصة "وتين".
النظام مصمم بحزم للتعامل مع البيانات المكانية `GeoJSON`، مدعوماً بخوارزميات أمان رياضي لمنع الاحتيال الجغرافي أو سوء الاستخدام (مثل إدخال مساحات تغطية لا نهائية أو مضلعات متقاطعة).

الإضافة الأبرز في هذا التحديث هي الربط المعماري بين الحذف/التعديل المكاني وبين **المهام البعدية غير المتزامنة (Asynchronous Background Tasks)** لضمان بقاء دورة حياة الزيارات (Visits) متوافقة تماماً مع المنطقة الجغرافية الجديدة للمزود.

## 2. بنية مسارات الـ API (Endpoints Architecture)

### Endpoint: `/api/v1/agencies/{id}/coverage/`

#### 2.1 الرفع والتحديث (POST / PUT)

- **الوظيفة:** استقبال مساحة التغطية ككائن GeoJSON.
- **المدخلات:** `Feature` أو `Polygon` أو `MultiPolygon`.
- **خط الأنابيب (Pipeline):**
  1. التحويل إلى كائن `GEOSGeometry` (معالجة الأخطاء إذا كان التنسيق تالفاً).
  2. طبقة الـ Serializer (`AgencyProfileSerializer.validate_coverage_polygon`):
     - **التحقق من النوع:** يرفض أي شيء غير Polygon أو MultiPolygon.
     - **الفحص الرياضي (Topology):** يمنع `empty` ويمنع `invalid` (مثل الخطوط المتقاطعة ذاتياً).
     - **الاتصال (Closed Ring):** يضمن إغلاق المضلع (نقطة البداية = نقطة النهاية).
     - **الحد الأدنى للرؤوس:** يفرض 3 رؤوس فريدة كحد أدنى (4 إحداثيات بإضافة نقطة الإغلاق).
     - **خوارزمية حساب المسطح الجغرافي (Area Calculation):** يتم إسقاط المضلع (Projection Transform) إلى مسقط محلي شديد الدقة لحساب المساحة بالكيلومتر المربع. وتم تحديد الـ SRID الافتراضي (مثلاً 32636 لمصر) بشكل ديناميكي من `settings.WATEEN_DEFAULT_UTM_SRID`. تُرفض أي تغطية تتجاوز 5000 كم مربع لمنع الاحتكار العبثي.
  3. **طبقة المعاملة (Database Transaction):** يتم حفظ الشكل في قاعدة البيانات.
  4. **مُشغّل ما بعد الحفظ (Post-Commit Hook):** (إصلاح حرج لـ Closure Capture Bug)
     يتم تمرير مُعرّف الوكالة كطُعم مباشر (`Default Argument`) لدالة اللامبـدا لضمان دقة التنفيذ:
     `transaction.on_commit(lambda aid=str(agency.id): re_evaluate_pending_visits.delay(aid))`

#### 2.2 الاسترجاع والخصائص (GET)

- **الوظيفة:** يحق لمدير الوكالة (أو الـ SuperAdmin) رؤية مسطح الوكالة الخاص به. يمنع منعا باتا (عزل المستأجرين Cross-Tenant Isolation) رؤية تغطية وكالات أخرى.
- **المخرجات (Outputs):**
  - يعاد كـ `GeoJSON Feature` جاهز للرسم على واجهة الويب (Leaflet).
  - يُحقن ببيانات مكانية محسوبة في الوقت الآني (On-the-fly):
    - المساحة بالكيلومتر المربع (`area_km2`).
    - الإحداثي المركزي الدقيق (`centroid`: lat, lng).
    - عدد النقاط/الرؤوس المكونة للمضلع (`vertex_count`).

#### 2.3 الحذف الآمن (DELETE)

- **الوظيفة:** إزالة نطاق التغطية الخاص بالوكالة وإيقاف استقبال طلبات في تلك المنطقة.
- **هندسة التضارب (Conflict Engineering):**
  آلية `select_for_update()`: تُقفل واجهة الوكالة لحظياً في قاعدة البيانات. يتم فحص الزيارات المعلقة (التي تكون في حالة ACCEPTED، EN_ROUTE، أو IN_PROGRESS).
  إذا كان هناك ممرضون في الطريق لمرضى أو زيارات قيد الإجراء، **يُرفض طلب الحذف** بوجود حالة 409 Conflict. لا يُسمح بتفريغ التغطية إذا كانت الوكالة ملتزمة حيوياً على الأرض.
- **ما بعد الحذف:** إعادة جدولة زيارات الـ PENDING_AGENCY إن وُجدت عبر `Celery`.

## 3. الخوارزميات وصيغ الأمان الرياضي (Algorithms & Security)

### أ. فخّ الحلقات المغلقة (Closure Capture & Memory Race Conditions)

كان هناك ثغرة خفية تحدث عند استخدام متغير الوكالة مباشرة داخل اللامبدا في مهام الـ Celery:

```python
# الوضع القديم الخطِر (يحتفظ بالمتغير كمرجع قابل للتغيير)
transaction.on_commit(lambda: re_evaluate_pending_visits.delay(str(agency.id)))
```

تم تطبيق خوارزمية **التجميد اللحظي (Value Freezing by Default Arguments)** التي تضمن ألا يتغير مُعرّف الوكالة في الذاكرة حتى موعد تنفيذ المهمة البعدية خلف الكواليس:

```python
# الوضع الحالي الآمن والمحصّن
transaction.on_commit(lambda aid=str(agency.id): re_evaluate_pending_visits.delay(aid))
```

### ب. الإسقاط الجغرافي وحساب المساحات (Spatial Transformation)

نظراً لأن قاعدة البيانات الجغرافية تحفظ الإحداثيات بنموذج `WGS 84` (خطوط الطول والعرض 4326)، فإن حساب مساحة الـ `Polygon` بهذه الدرجات ينتج أرقاماً لا معنى لها على أرض الواقع المائي.
الخوارزمية تقوم بعملية **نسخ (Clone)** ثم **إسقاط وتصفيف (Transform)** المضلع على نظام **UTM** (نظام الإحداثي العالمي الموزع - في مصر نطاق Zone 36N ورقمه SRID 32636).
بعد الإسقاط (المقاس بالمتر)، يُحسب السطح وتُرفع المساحة بالأمتار المربعة.
كما تمت معالجة ثغرة الفشل الصامت برفع استثناء مباشر `ValueError` لمنع اختراق المساحات الوهمية إذا فشل الإسقاط.
